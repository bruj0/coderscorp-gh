Production lines

How the work gets made
LINE 01

Specification first

A build starts as a written contract, not a prompt. The specification is the artifact; the code follows it.

LINE 02

Reproducible delivery

Infrastructure is declared, pinned and re-runnable. A deployment is a function of a commit, never of a shell history.

LINE 03

Boring operations

Services run under systemd, expose health checks, and repair themselves. Nothing depends on a developer being awake.

LINE 04

Open by default

The catalogue is built from public repositories, and the tooling that builds the catalogue is public too.

03

Method

Rules the factory holds to

§1 Ships or it does not exist

A repository counts when something runs against it. Half-finished work stays private until it works end to end.

§2 The second run must be quiet

Every delivery is idempotent. A repeat install reports no change, which is the only honest proof that the automation is correct.

§3 Measure, then claim

Numbers in this catalogue come from the GitHub API at build time. Nothing is hand-maintained, so nothing drifts quietly.

§4 Fail loudly at the boundary

Errors carry the trace that produced them and the command that investigates them. A silent failure is a design defect.
